# Project plan — orb-slam-mono

## Goal and scope

Build an original, inspectable monocular ORB feature-based visual localization and sparse mapping pipeline for GPS-denied navigation research. The eventual data flow is image → ORB features → descriptor/geometric filtering → monocular initialization → map points → map-based PnP tracking → keyframes/map maintenance → local bundle adjustment → trajectory/map output → offline evaluation and failure analysis. Loop closure is optional.

M5-A frozen-baseline scoring and M5-B restarted-window evaluation are complete. M5-B preserves the corrected online estimator and measures full and independently restarted KITTI windows, eligible segment accuracy, exact-gap relative errors, runtime, and Windows process working set. Its go/no-go decision supports only a bounded M5-C visual demonstration with coverage and scale limits disclosed; any M5-C implementation needs separate authorization. See `artifacts/m5b-final-evaluation/REPORT.md` and `STATUS.md` for measured evidence.

**Scientific invariants:** KITTI ground-truth poses never enter online estimation, map initialization, scale selection, or parameter tuning per frame. Monocular translation and reconstruction have unknown global scale, with scale drift expected over time. Ground truth may enter only an offline evaluation module; use Umeyama Sim(3) alignment there for ATE and explicitly report the alignment, raw scale behavior, and drift. A successful descriptor match is not a geometric inlier.

Start development on a few hundred frames of a KITTI odometry training subsequence (suggested: sequence 00, frames 0–299), then try other short subsequences. Keep the first test data slice and parameter set fixed for comparisons; do not use the full sequences as the first target.

### M1 — calibrated image pair, ORB, descriptor matching (complete)

### M2 — two-view geometry and monocular initialization (technical acceptance complete; conservative limitations documented)

- Add inspectable normalized point handling, essential-matrix RANSAC, `recoverPose`, cheirality/parallax checks, and triangulation with reprojection/depth filtering.
- On a controlled synthetic 3D scene with known calibration, recover rotation and translation **direction** within stated tolerances; do not claim translation magnitude. Reject pure rotation/low-parallax initialization and report the reason.
- On a fixed short KITTI slice, log candidate matches, essential-matrix inliers, parallax, accepted 3D points, and rejected initialization attempts; produce an initialization visualization without ground-truth input.

M2 synthetic acceptance: 450 visible noncoplanar landmarks, 0.35 px Gaussian noise, 0.8 scene-unit baseline, and 3° nominal rotation yield 1.25° rotation error, 1.84° translation-direction error, 427 essential/pose inliers and accepted points, and 4.04° median parallax (seed 7). The rendered-image ORB path also initializes. Pure rotation and 0.005 scene-unit baseline tests reject. The initial implementation passed 27 tests, including the original ten. The later correctness audit brought this to 34 tests; the genuine KITTI experiment and optional integration test are recorded below.

**M2 audit refinement:** A rejected attempt may retain provisional diagnostic counts but must expose zero usable map points and no public camera-2 pose. Exports must label rejection and replace stale outputs from earlier accepted runs. Added cheirality-consensus and rotation-only residual quality gates after a 0.15-baseline case was falsely accepted with reversed translation direction. A fixed 5-seed × 8-condition synthetic study retains 5/5 acceptance for each well-conditioned/noisy/outlier group, reduces weak-baseline acceptance from 4/5 to 2/5, and rejects all five very weak and pure-rotation cases. Full CSV/JSON results are generated but ignored by Git. The offline 3D report separates scale-only fit from a true-pose triangulation reference. Genuine KITTI data was then obtained and tested as described below.

**Genuine KITTI validation baseline:** The user-provided official grayscale/calibration ZIPs supplied unchanged sequence-00 `image_0` frames 0–299, matching `P0`, and timestamps. Selective extraction verified CRCs and image dimensions. With the then-unchanged defaults, all predetermined pairs 0→1, 0→5, 10→15, 20→25, 40→45, 60→65, and 80→85 were evaluated and exported, including every rejection. Outcomes were 5/7 accepted, 2/7 rejected; the original 34 tests plus an optional real-data smoke test passed. Full baseline results are preserved in ignored `artifacts/kitti-00-validation/` and copied under `artifacts/kitti-00-pose-audit/baseline-original/`. Pair 20→25 passed all original gates with a 41.82° estimated rotation; the later official-pose audit below confirms this was wrong. At this baseline stage, M3 work had not started.

**M2 offline pose audit and reliability correction:** The user-provided official `poses/00.txt` is read only by `kitti_pose_evaluation.py`, never by the estimator or dataset loader. Ground truth is `T_wc`; compare the estimator with `inverse(T_wc_j) @ T_wc_i`. The original 20→25 pose has 42.18° rotation and 110.86° translation-direction error, despite 79 essential/pose inliers and subpixel reprojection error. Its essential correspondences are spatially concentrated and the result changes substantially with match ordering. A configurable, eight-trial pose-stability gate rejects it without choosing a replacement pose or using truth. That earlier angular-only gate left six other original decisions and all five predetermined held-out decisions unchanged; original acceptance became 4/7, held-out remained 1/5. Its 40-run synthetic acceptance pattern was preserved; controlled large-rotation, forward/lateral, planar/near-planar, and nonuniform-feature cases tested the gate's limits. Real-pair pose accuracy is reported only for accepted estimates. **M2 reliability remains under review** because four held-out pairs reject under existing cheirality/parallax gates and only one held-out pose is independently scored. This conservative failure rate remains a limitation for sequence tracking; additional fixed-data validation should avoid per-pair tuning and ground-truth-assisted scale.

**M2 accepted-trial gate review:** The earlier angular gate could count rotations from eight rejected trials and still accept the original pose. The corrected rule requires 4 fully accepted trials as well as 4 candidate rotations and ≤10° median disagreement. All 12 predetermined KITTI decisions remain unchanged, including 20→25 rejection. The 40-case synthetic grid retains 5/5 acceptance in each well-conditioned/noisy/outlier group, but weak-baseline acceptance falls from 2/5 to 0/5. An interim run had two failing acceptance expectations: small translation with moderate rotation and a planar scene had only 2/8 and 1/8 fully accepted trials. A later truth-based review found their one-shot rotation/direction errors to be 1.212°/10.065° and 3.798°/24.258°, with rejected permutations reaching 172° and approximately 85–91° direction error respectively. The expectations were updated to require conservative rejection while retaining truth-based and public-map assertions. **M2 technical acceptance is complete: 44/44 tests pass, 0 skipped; all fixed KITTI and synthetic demo outcomes are reproduced.** M3 was subsequently authorized and implemented with sequence-level pair retry after sufficient motion.

### M3 — adaptive initialization, sparse map, PnP tracking (complete for defined criteria; real-image continuity limited)

- A deterministic anchor search attempts gaps 3, 5, 7, 9, and 11 by default, preserving M2 gates and replacing exhausted anchors. Accepted `accepted_mask` indices map through the original ORB `DMatch.queryIdx/trainIdx` identities into persistent `MapPoint` observations.
- `Frame`, `MapPoint`, and `SparseMap` retain segment-local `T_cw` poses and globally distinct point IDs. Descriptor association to a fixed initial point set feeds calibrated PnP-RANSAC, inlier-only refinement, depth, inlier-fraction, and reprojection gates. Tracking loss invalidates the current pose and starts a fresh segment after subsequent two-view success; earlier frames remain unestimated.
- On physical rendered images, initialization chooses 0→3, creates 229 points, and PnP tracks frames 4–11. Offline known-baseline scoring gives median/max rotation error 0.416°/0.603° and position error 0.034/0.072 scene units; the metric baseline never enters online estimation. A blank frame causes loss and a separately identified fresh segment in tests.
- On genuine KITTI 00 frames 0–299, all 300 outcomes are recorded: 191 initializing, 97 tracking (13 initialization-second frames and 84 PnP frames), and 12 lost. There are 84 initialization attempts, 13 accepted pairs, 12 PnP failures, and 12 reinitializations. The longest valid segment has only 13 poses. The fixed initial map and single anchor descriptor limit continuity; M3 demonstrates genuine tracking but does not establish reliable long-run trajectory accuracy. See `STATUS.md` for results and ignored outputs.
- The recovery-state closure correction makes `max_recovery_frames` a count of processed frames after failed PnP, then enters terminal LOST if the search is exhausted. It preserves accepted maps, invalidates failed poses, clears obsolete anchors, and requires an explicit fresh tracker for another run. Regression coverage and separate synthetic timeout output verify this path. The corrected KITTI 0–299 run has the same 300 decisions and poses as the original, with zero recovery timeouts; **62 tests pass**. Failure diagnostics now separate accepted and rejected PnP populations. Longer real-image tracking and independent segment pose accuracy remain unproven.

### M4 — keyframes, map management, local optimization (complete for defined functional and safety criteria)

- Add documented keyframe insertion/culling rules and map-point creation, observation updates, outlier removal, and culling.
- Optimize a local sliding window of approximately **5–10 keyframes** using `scipy.optimize.least_squares` with a sparse Jacobian structure; fix gauge freedoms and keep nonlocal states outside the active variable block.
- A synthetic optimization test must reduce median reprojection error without increasing it for accepted observations. Assert active keyframe count stays within the configured window, and report runtime and memory on the fixed KITTI slice.

**M4 acceptance evidence:** The 80-test suite passes with no skips. Keyframe identity, window bounds, segment isolation, image-based landmark triangulation, bounded Hamming-medoid evidence, underconstrained BA rejection, fixed-gauge sparse BA, and failure rollback have direct tests. A varied-visibility rendered sequence gains 160 triangulated points and improves valid poses from 12 to 15 with map growth and descriptor maintenance; its offline full-M4 first-segment median/max rotation error is 1.265°/2.059° and center error 0.145/0.346 scene units after evaluation-only known-baseline scaling. The fixed KITTI 00 0–299 four-way comparison gives 97 baseline, 126 growth, 145 growth-plus-descriptor, and 144 full-M4 valid poses, with longest spans 13, 30, 34, and 60. Full M4 accepts four of ten bounded BA windows and rejects six for held-out reprojection regression. Its 156 unestimated KITTI frames, unscored real trajectory accuracy, and CPU cost remain explicit limitations. Full evidence and commands are in `STATUS.md`; outputs are ignored under `artifacts/m4-kitti-00-final/` and `artifacts/m4-synthetic-varied-final/`. No M5 work is included.

**Targeted M4 correction, independently accepted:** The preceding figures remain the preserved original experiment. BA now validates all untrained stored observations affected by candidate camera/landmark changes, including outside-window frames, with median/p90/maximum and newly-over-limit checks; insufficient validation rejects. The separate corrected synthetic run retains 12/13/15/15 valid poses; its full BA candidate rejects external regression and offline full rotation/center median errors become 1.414°/0.145 scene units. The separate corrected KITTI run retains 97/126/145 poses in its first three ablations, and full M4 has 145 valid poses, a 34-pose longest span, and 0/10 BA updates applied. The original 60-pose advantage does not survive the stronger gate. Sparse local BA remains implemented and controlled safe candidates apply, but real-image BA benefit is unproven. See `STATUS.md` for corrected paths, tests, runtime, and remaining limits; do not infer M5 trajectory accuracy from this comparison.

### M5 — trajectory/map output and failure analysis (planned)

- Export an unscaled estimated trajectory and sparse map, plus per-frame diagnostics: detected features, descriptor matches, essential-matrix inliers, PnP inliers, reprojection error, tracking state, and failure reason.
- In a separate offline evaluator, use Umeyama Sim(3) to align estimated and training-set ground-truth trajectories for ATE. Report aligned ATE, unaligned trajectory, fitted scale, per-segment scale drift, lost-frame rate, and diagnostic timelines. Never feed the fitted transform or ground truth back into online tracking.
- Reproduce plots/metrics for at least two fixed short KITTI subsequences, including one failure case. Record exact data ranges and configuration in the report.

### M6 — loop closure (stretch goal; not required for core completion)

- Only after M5, consider place recognition, geometric verification, and graph correction. Measure drift before/after on a looped sequence and inspect false-positive handling. Core completion does not depend on this milestone.

### Optional final visualization/export (outside core SLAM)

- Export sparse 3D landmarks to PLY and estimated camera poses/trajectory to documented JSON with coordinate frame, transform direction, units, and unknown monocular scale stated explicitly.
- An optional Blender Python script may import these exports to show camera frustums, sparse points, trajectory lines, animation, and rendered views. Keep Blender outside runtime dependencies and SLAM mathematics. On the user-confirmed RTX 3050 Ti, prefer NVIDIA OptiX only after driver/Blender compatibility checks; keep CPU rendering as a fallback, especially when a scene exceeds 4 GiB VRAM. GPU acceleration is optional and never required for core SLAM.

## Working rule

Use milestone-based headings in all project Markdown; omit development calendar dates and timestamps while preserving publication years, version numbers, dataset identifiers, and numerical results. Any future commit requires explicit approval and a newly supplied author date, committer date, and timezone; do not reuse a previously authorized date. Do not advance past M4 without an explicit request.
